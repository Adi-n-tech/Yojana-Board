Internal Task Management Platform
Product, UI, Technical Architecture & Development Roadmap
 Working name: WorkFlow Web-first internal Linear alternative with Google Sheets storage and GitHub integration

1. Executive Summary
WorkFlow is an internal project and task management platform designed to reduce reliance on paid Linear seats and Excel-based task tracking. The first version will provide a fast, Linear-inspired web experience for projects, features, bugs and tasks, while using Google Sheets as the initial persistence layer and GitHub as the development workflow integration.
The architecture should deliberately separate the UI and business logic from the storage implementation. Google Sheets is therefore an MVP storage adapter rather than a permanent architectural dependency. If usage grows, the storage layer can be migrated to PostgreSQL or another database without redesigning the product.
The product will be built web-first. A desktop client can later be introduced using Tauri and the same backend APIs, adding global shortcuts, system notifications and desktop-specific capabilities.
2. Product Vision
Build an internal tool that is:
Faster and simpler than Jira for everyday work.
More structured and collaborative than Excel.
Close to Linear in interaction quality and information density.
Deeply integrated with GitHub for software development.
Cheap to operate and simple to maintain.
Designed to evolve toward a real database when scale requires it.
Eventually AI-native for task creation, search, summaries and reporting.
3. Goals and Non-Goals
Goals
Replace Excel-based project/task tracking for internal teams.
Provide projects, tasks, features, bugs, priorities, assignees, labels and due dates.
Provide List and Kanban views.
Provide My Work and project dashboards.
Create GitHub issues automatically from tasks.
Support GitHub issue/PR synchronization in later phases.
Use Google Sheets without exposing Google credentials to the browser.
Maintain a clean abstraction so storage can later move to PostgreSQL.
Non-Goals for MVP
Full Jira/Linear feature parity.
Complex custom workflows.
Advanced time tracking.
Billing/subscription functionality.
Native mobile apps.
AI automation before the core workflow is stable.

12. Backend Architecture

Do not put business rules inside React components. Keep API/service logic separate so it can later move to a dedicated backend if scale requires it.
13. Security
Never expose Google or GitHub secrets in browser code.
Store secrets in server-side environment variables.
Validate workspace membership on every protected API operation.
Enforce role/permission checks server-side.
Validate GitHub webhook signatures.
Use least-privilege OAuth scopes.
Keep audit/activity records for important changes.
Do not store access tokens in Google Sheets.

19. Scalability and Migration Strategy
Google Sheets is appropriate for the first internal version, but it should not be assumed to be the final database. The migration trigger should be based on actual usage: concurrency, task volume, query complexity, latency and reliability requirements.
Current: Frontend → API → Google Sheets  Future: Frontend → API → PostgreSQL  Migration: Google Sheets → migration script → PostgreSQL
Because repositories are abstracted, the migration should primarily replace the persistence adapter rather than requiring a rewrite of the product.
20. Suggested First Pilot
Build the MVP with the core task workflow only.
Pilot with 3–5 internal users.
Run one or two real projects through it.
Continue Excel in parallel for safety during the pilot.
Collect feedback on task creation, board workflow, search and GitHub integration.
Fix friction before adding dashboards or AI.
Expand to the wider team only after the core workflow is reliable.

22. Recommended Product Direction
The strongest strategy is not to build a complete Linear clone. Build the smallest internal system that makes the existing workflow better: Excel-like simplicity, Linear-like task management and GitHub-native development tracking.
The first milestone should therefore be: Google Login → Project → Task → Kanban → Google Sheets persistence → GitHub Issue creation. Once that workflow is stable and adopted, add two-way GitHub synchronization, dashboards, notifications, AI and finally the desktop client.
